# Contributing to Wompi Hash Validator

Thank you for your interest in contributing to the Wompi Hash Validator project! We welcome all contributions, whether it's reporting bugs, suggesting new features, or submitting pull requests.

## How to Contribute

### Reporting Issues

If you encounter any issues while using the library, please let us know by opening an issue in the [GitHub Issues](https://github.com/cabrera-evil/wompi-hash-validator/issues) section. When reporting an issue, please include the following details:

- A clear and descriptive title.
- Steps to reproduce the issue.
- Expected behavior and actual behavior.
- Relevant code snippets (if applicable).
- Any other information you believe is relevant.

### Suggesting Enhancements

We value feedback and suggestions for improving the library. If you have an idea for a new feature or enhancement, please create an issue labeled as `enhancement` and describe your suggestion in detail.

### Submitting Pull Requests

1. Fork the repository and clone it to your local machine.

   ```bash
   git clone https://github.com/cabrera-evil/wompi-hash-validator.git
   ```

2. Create a new branch for your feature or bug fix:

   ```bash
   git checkout -b feature/your-feature-name
   ```

3. Implement your changes.

4. Follow the [Development Guide](DEVELOPMENT.md) to ensure your code meets the project's standards.

5. Test your changes thoroughly.

6. Commit your changes using [conventional commit messages](https://www.conventionalcommits.org/).

   ```bash
   git commit -m "feat: add new feature"
   ```

7. Push your branch to your forked repository:

   ```bash
   git push origin feature/your-feature-name
   ```

8. Open a pull request in the main repository. Provide a clear and descriptive title and description for your pull request.

### Code Style

- Follow the coding standards defined by the project.
- Run `pnpm lint` and `pnpm format` to ensure code quality.

### Commit Message Guidelines

We use the [Conventional Commits](https://www.conventionalcommits.org/) specification for commit messages. Please ensure your commit messages follow this format:

```
type(scope?): subject

body (optional)
```

Examples:

- `feat: add URL validation feature`
- `fix: correct hash calculation bug`
- `docs: update README with installation steps`

### Code of Conduct

Please note that this project is governed by a [Code of Conduct](CODE_OF_CONDUCT.md). By participating, you agree to abide by its terms.

## Getting Help

If you have any questions or need help with your contributions, feel free to reach out by opening an issue or joining our community discussions.

Thank you for your contributions!
